# 市政道路桥梁养护管理平台

覆盖道路巡查、桥隧定检、路面病害、交安设施、绿化管养、除雪防汛及养护工程管理的市政道桥全要素养护后台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 启动门禁（养护工程）

工程启动检查是四级状态机门禁，只能逐级推进，跳级、倒序或覆盖已批准工程一律
返回 `409` 阻断：

1. **基础数据核验**：在工程台账、施工路段、材料计划（跨运行空间）之间做相符性探测，
   核验路段边界桩号、材料计划与材料台账的一致性、数据源可达性。
2. **配置探测**：逐件核验前置件（施工许可证、交通组织方案等）与运行空间配置，
   配置或前置件失败必须阻断启动。
3. **外部服务连通**：探测外部依赖服务；**超时**与**不可达**是两条独立结论，
   各自有处置路径，不共用兜底。
4. **开放发布**：冲突里程碑以**计划基线**裁决并回写台账，未完成里程碑按基线排期；
   逐级通过后才允许"批准开工"。

异常分流（分别处置，不合流兜底）：

| 场景 | 处置路径 |
| --- | --- |
| 无工程（空态） | 登记空批次结论，不产生待办 |
| 边界缺失 / 材料缺失 / 前置件缺失 / 配置缺失 | 各自补齐后重新核验当前级 |
| 外部服务超时 | 重试连通（区别于不可达） |
| 数据源不可达 | 转人工核验通道，禁止按空态放行 |

其他规则：

- 检查结论回写三处：**工程台账**（`门禁结论/门禁阶段`）、**路段待办**面板、
  **运行日志**面板（前端"启动门禁"页与"路段管理"页可见）。
- 存量/历史工程按**存档资料**迁移回填；已竣工历史工程保留在台账、不参与启动门禁；
  迁移与任何探测/复位都**不覆盖已批准工程**。
- 探测任务按**批次**组织：建批幂等，完成项不重跑；**复位**只把未完成项回到待执行，
  已完成项保留，复位后继续未完成项。
- 接口前缀 `/api/readiness`（`summary`、`gates`、`advance`、`resolve`、`todos`、
  `logs`、`probes/batch`、`probes/reset`、`faults`），`/faults` 用于演示超时/不可达分流。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
